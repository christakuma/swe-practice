Applying the suggestion automatically at submission would make the queue self-filling and would make an override impossible to honour: a card is replaced rather than versioned (`sqlite/reviews.py`), so a correction would have to be applied on top of a schedule already moved, compounding one piece of evidence twice. Pressing it once is the only shape in which the suggestion can be a suggestion. Forgetting to press it is not a hole. An exercise with no card is offered by `ReviewQueue` as new, which is where it was before — so the cost of skipping this is that the tool keeps no memory of the attempt, not that the exercise disappears. **Four buttons from the enum, not four strings written here.** `grades` is a Jinja global built from `Grade` in `app.py`, so a fifth bucket would appear rather than be missed. The suggested one is marked rather than preselected: there is no "submit" to press afterwards, so every button is a decision and the mark is a recommendation rather than a default someone can fail to notice. One `id`, one section, every state. The response to a press replaces this whole element, which is why the refusal renders inside it too — a reader looking at the schedule block should not have the block vanish to tell them something about it. #}
