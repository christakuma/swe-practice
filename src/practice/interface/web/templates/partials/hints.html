The order is the aggregate's: `reveal_next_hint` hands back the next one and refuses once they run out, so there is no request that skips ahead. **Already-revealed hints are rendered from the event log**, like the console transcript, so a reload shows what was revealed rather than resetting the ladder — and so a hint revealed from one tab is there in the other. **No confirmation dialog on the button, and that is a decision rather than an omission.** Revealing is recorded, so the first draft put `hx-confirm` on it -- and a blocking native dialog in front of something a solver does three or four times an attempt buys a worse experience than the honesty is worth. The control says "recorded on the attempt" beside it instead, which is the same information without the interruption. `hx-confirm` stays where it belongs: on Submit, which finishes the attempt and cannot be undone. #}
