{# The repository, as it stands. The panel PLAN.md §8.4 calls the piece that makes git scenarios teachable. **Re-rendered whole on every command, out of band.** There is no diffing and no client-side model of a repository: the server reads the repo again and sends the panel back, and htmx replaces it by id. A panel that tried to patch itself would need to know which commands move which refs, which is a second, worse copy of git. **HEAD first, and loudly when it is detached.** Detached HEAD is the state these exercises are mostly *about* and the one a terminal hides behind a paragraph of advice nobody reads twice. The commit is named alongside it, because "detached" on its own is a diagnosis with the evidence withheld. Order is deliberate: where you are, then what the worktree looks like, then what the refs say, then the stash. It is the order someone reads a broken repository in — and the stash is last because it is the thing people forget, which is exactly why it is on the page at all rather than behind a command. #}
